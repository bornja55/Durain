## 3. บัค #2 — ลูกค้าสแกน QR ค้าง

- [ ] บัญชีลูกค้า สแกน QR บนแท็กต้นไม้ → เห็นหน้าข้อมูลต้นไม้ (รหัส/สายพันธุ์/อายุ/ผลคงเหลือ)
      ไม่ค้างที่ `liff.init...` อีก
- [ ] สแกนด้วยกล้องมือถือปกติ (ไม่ผ่าน LINE) → เปิดได้เหมือนกัน
- [ ] ทดสอบ QR ต้นที่ยังไม่ลงทะเบียน → ขึ้น "ไม่พบต้นไม้รหัส ..." ไม่ใช่หน้าขาว
- [ ] **ต้นที่มีหลายรูป** → เลื่อนดูได้ครบทุกรูป + มีปุ่ม ‹ › + ตัวนับ "2 / 5" มุมขวาล่าง
- [ ] **แตะรูป → เปิด popup รูปใหญ่** → เลื่อนซ้าย/ขวาใน popup ได้ (วนรอบ) → กด × หรือแตะพื้นหลังเพื่อปิด
- [ ] ต้นที่มีรูปเดียว → ไม่มีปุ่มลูกศร/ตัวนับ แต่ยังแตะดูรูปใหญ่ได้
### ประวัติต้นไม้

- [ ] ต้นที่เคยตัดขาย/รายงานเสียหาย → เห็นรายการเรียงใหม่สุดขึ้นก่อน + วันลงทะเบียนต้นอยู่ล่างสุด
- [ ] **ตรวจว่าไม่มีตัวเลขราคาโผล่ที่ไหนเลย** (แสดงแค่ จำนวนลูก / เกรด / น้ำหนัก / ฤดูกาล)
- [ ] ต้นที่มีประวัติเกิน 10 รายการ → มีปุ่ม "ดูทั้งหมด (อีก N รายการ)" กดแล้วแสดงครบ
- [ ] ต้นที่เพิ่งลงทะเบียน ยังไม่มีประวัติ → ขึ้น "ยังไม่มีประวัติการบันทึกสำหรับต้นนี้" ไม่ใช่ช่องว่าง

### สิทธิ์ในหน้าต้นไม้ (ปุ่มบันทึกต้อง login ก่อน)

- [ ] **สแกนครั้งแรก (ยังไม่ login)** → เห็นแค่ข้อมูลต้นไม้ + ลิงก์เล็ก "🔑 เจ้าหน้าที่สวน — เข้าสู่ระบบ" **ไม่มีปุ่มบันทึก**
- [ ] บัญชีลูกค้า กดลิงก์เข้าสู่ระบบ → login ผ่าน → กลับมาหน้าเดิม → **ยังไม่มีปุ่มบันทึก** (ถูกต้อง)
- [ ] บัญชีคนสวน กดลิงก์เข้าสู่ระบบ → login → กลับมา**หน้าต้นไม้เดิม** (ไม่ใช่ Dashboard) → เห็นปุ่มบันทึก + บรรทัด "เข้าสู่ระบบเป็น: คนสวน"
- [ ] คนสวนสแกนต้นที่ 2 ต่อ → **เห็นปุ่มเลยไม่ต้อง login ซ้ำ** (session จำไว้ 6 ชม.)
- [ ] กดปุ่ม "บันทึกตัดจำหน่าย" → เปิดแชทบอทพร้อมข้อความ กดส่งแล้วเข้า flow

## 4. บัค #3 — หน้าเว็บแก้ role ไม่มีปุ่มเซฟ

- [ ] เข้า Dashboard → แท็บผู้ใช้ → เปลี่ยน dropdown ของคนอื่น
- [ ] มีกล่องยืนยันขึ้น → กด OK → ขึ้น "อัปเดตสิทธิ์สำเร็จ" + ตาราง refresh
- [ ] กด Cancel → dropdown เด้งกลับค่าเดิม
- [ ] เช็คชีต "ผู้ใช้" ว่าค่าเปลี่ยนจริง + คนนั้นเปิดแชทใหม่แล้วเมนูเปลี่ยนตาม

## 6. Flow ตัดจำหน่าย (มีบั๊กที่เพิ่งแก้ — ทดสอบให้ครบ)

> เดิม: กด "ส่งรูปครบแล้ว" แล้วบอทเงียบ ทำรายการไม่จบเลย

- [ ] คนสวน: สแกน → เลือก "ตัดขาย" → จำนวน → เกรด → น้ำหนัก → ราคา → ถ่ายรูปตาชั่ง
- [ ] กด "ส่งรูปครบแล้ว" → **ต้องขึ้นการ์ดสรุปรายการ** (จุดที่เคยเงียบ)
- [ ] กดยืนยัน → "ส่งขออนุมัติเรียบร้อย" + มีแถวใหม่ในชีต "คิวรออนุมัติ"
- [ ] ยังไม่ส่งรูปแล้วกด "ส่งรูปครบแล้ว" → ขึ้นเตือน "ยังไม่ได้ส่งรูปเลยครับ"
- [ ] ระหว่างรอรูป พิมพ์อะไรก็ได้ → บอทบอกให้ส่งรูป ไม่เงียบ
- [ ] flow "ผลเสียหาย" → พิมพ์ "ข้าม" → ต้องถูกห้าม
- [ ] เจ้าของกดอนุมัติ → เช็คชีต "ผลผลิต" ว่า ตัดแล้ว/คงเหลือ ขยับถูก

## 7. Flow ลงทะเบียนต้นไม้

- [ ] คนสวนลงทะเบียนต้นใหม่จนจบ → ได้รหัส T-xxx ไม่ซ้ำของเดิม
- [ ] เจ้าของอนุมัติ → มีแถวใหม่ในชีต "ต้นไม้" + รูปเปิดดูได้จาก Drive
- [ ] **ทดสอบ race:** ให้คนสวน 2 คน กดยืนยันลงทะเบียนพร้อมกัน → ต้องได้รหัสคนละตัว
      (จุดที่เพิ่งใส่ LockService — เป็นเคสที่ automate ไม่ได้จริง)

## 8. Error Log

- [ ] ทำให้เกิด error สักครั้ง (เช่นลบชีต "ผลผลิต" ชั่วคราวแล้วสแกน) → มีแถวใหม่ในชีต "Error Log"
- [ ] ยืนยันว่าไม่มี ERROR_LOG ไหลเข้าชีต Config อีก
- [ ] **ชื่อชีตต้องเป็น `Error Log` ตรงตัว** (มีช่องว่าง L ใหญ่) ไม่งั้น log เงียบหาย

## หมายเหตุ: ทำไมข้อเหล่านี้ automate ไม่ได้

| เรื่อง | เหตุผล |
|---|---|
| Rich Menu จริง | ต้องยิง LINE API จริงและดูผลบนมือถือ — mock ยืนยันได้แค่ว่า "โค้ดยิง ID ถูกตัว" ไม่ได้ยืนยันว่า ID นั้นมีอยู่จริงบน LINE |
| การแสดงผลหน้าเว็บ | ต้องเปิดในเบราว์เซอร์/LINE จริง (GAS iframe มีพฤติกรรมเฉพาะตัว) |
| กล้อง/สแกน QR | ต้องใช้มือถือจริง |
| อัปโหลดรูปเข้า Drive | ต้องมีสิทธิ์ Drive จริง |
| Race condition จริง | ต้องมี 2 request ชนกันจริงบน GAS — mock พิสูจน์ได้แค่ว่า lock ถูกเรียก/ปล่อยครบ |
| LINE Login OAuth | ต้อง handshake กับ LINE จริง |
