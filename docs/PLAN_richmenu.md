## 2. ทำไมถึงเป็นแบบนี้ (สาเหตุ ไม่ใช่ความสะเพร่า)

**ปุ่มคนสวน 1-2 ซ้ำ** — ตอนออกแบบตั้งใจให้แยก flow "ตัดจำหน่าย" กับ "บันทึกผลผลิต" ตั้งแต่กดปุ่ม แต่ **กล้อง QR ของ LINE ไม่ส่งข้อมูลกลับมาว่าผู้ใช้กดปุ่มไหนมา** — มันแค่เปิด URL ที่อยู่ใน QR เท่านั้น ระบบจึงแยกไม่ออก สุดท้ายทั้งสองปุ่มจึงทำงานเหมือนกันโดยปริยาย

**ปุ่มผู้บริหาร 3-6 ซ้ำ** — Dashboard เป็นหน้าเว็บหน้าเดียวที่มีแท็บอยู่ข้างใน (`tab-overview`, `tab-map`, `tab-pending`, `tab-trees`, `tab-income`, `tab-users`) แต่**ยังไม่รองรับการเปิดตรงไปที่แท็บใดแท็บหนึ่ง** — ตรวจแล้วไม่มีโค้ดอ่าน `?tab=` หรือ `#hash` เลย ทุกปุ่มจึงเปิดมาที่แท็บแรกเหมือนกันหมด

**ปุ่ม "AppSheet"** — เป็นซากจากตอนที่ยังคิดจะใช้ AppSheet ตอนนี้ไม่มีแล้ว

## 3. บริบทที่เปลี่ยนไป (ต้องคิดใหม่ทั้งเมนู ไม่ใช่แค่ซ่อมปุ่มซ้ำ)

1. **หน้า `TreeInfo.html` ใหม่** — สแกน QR แล้วเจอหน้าข้อมูลต้นไม้ที่มีปุ่ม "บันทึกตัดจำหน่าย" และ "บันทึกผลผลิต" อยู่ในหน้าแล้ว → **การแยก flow ตั้งแต่ Rich Menu ไม่จำเป็นอีกต่อไป** ปุ่มคนสวน 1-2 ควบเป็นปุ่มเดียวได้
2. **ฟีเจอร์บันทึกการขายรายวัน (`SALE_ROUND`)** — ยังไม่มีปุ่มใน Rich Menu (ตอนนี้ซ่อนอยู่ในเมนู "ภาพรวม" + พิมพ์ `บันทึกการขาย`) → **นี่คืองานที่เจ้าของต้องทำทุกวัน ควรได้ปุ่มระดับบนสุด**
3. **role `admin` ใช้เมนูเดียวกับเจ้าของ** — ไม่ต้องทำเมนูที่ 4

## 7. เทสต์ที่จะเพิ่ม (กันปัญหาเดิมซ้ำ)

ปัญหา "หลายปุ่มไปที่เดียวกัน" เป็นแบบเดียวกับบั๊ก `SALE_ROUND` ที่ไม่มีปุ่ม — **โค้ดถูกแต่ผู้ใช้ใช้ไม่ได้** เทสต์ปกติจับไม่ได้ จึงต้องมีเทสต์เฉพาะ:

# ส่วนที่ 2 — ผังล่าสุด + Tab Deep-link

## 9. ผังเมนูเจ้าของสวน (ตามที่ผู้ใช้เสนอ)

### ตอบคำถามที่ถามมา

**"ปุ่มสแกนต้นไม้ แทน ปุ่มจัดการต้นไม้"** → ✅ **เห็นด้วยเต็มที่**
เจ้าของก็เดินสวนเหมือนคนสวน ต้องสแกนบันทึกเองบ่อย ส่วน "จัดการต้นไม้" เป็นงานนั่งโต๊ะที่เข้าจากเว็บได้อยู่แล้ว — เอาช่องที่มีค่าที่สุด (Rich Menu) ให้งานที่ทำบ่อยกว่าถูกต้องแล้ว

**"ปุ่มภาพรวม เปลี่ยนเป็น ระบบจัดการ"** → ✅ **ดี แต่ขอเสนอให้แยกเป็น 2 ปุ่ม**

เหตุผล: ถ้ายุบ "ภาพรวม" ทิ้งแล้วเหลือแต่ "ระบบจัดการ" ปุ่มเดียว การดูรายงานเร็วๆ จะต้องกด 2 ครั้งทุกครั้ง ทั้งที่เป็นสิ่งที่ดูบ่อยที่สุด

แยกเป็น **📊 รายงาน** (ตัวเลขสรุปในแชท ดูปุ๊บได้ปั๊บ) กับ **⚙️ ระบบจัดการ** (ประตูเข้าเว็บทุกแท็บ) จะได้ไม่ทับกัน — และเป็นการแก้ปัญหา "หลายปุ่มไปที่เดียวกัน" ที่ต้นเหตุ เพราะแต่ละปุ่มมีหน้าที่ชัดเจนคนละอย่าง

## 10. Tab Deep-link — spec ครบทุกกรณี

### แท็บที่มีจริงในระบบ (ตรวจจาก `Dashboard.html`)

`overview` · `map` · `pending` · `trees` · `income` · `users`

ทุกแท็บสลับผ่าน `switchTab(tabId, btn)` ใน `Dashboard.js.html:173` ซึ่งโหลดข้อมูลของแท็บนั้นให้เองอยู่แล้ว (`PendingVM.load()`, `IncomeVM.load()`, ฯลฯ) — **deep-link จึงแค่เรียกฟังก์ชันนี้ตอนหน้าโหลดเสร็จ ไม่ต้องเขียน logic โหลดข้อมูลซ้ำ**

### สิ่งที่ต้องแก้ (3 ไฟล์)

**1. `Code.gs` — `doGet()` รับและตรวจ `tab`**

```js
const VALID_TABS = ['overview', 'map', 'pending', 'trees', 'income', 'users'];
// อ่านจาก e.parameter.tab -> ถ้าไม่อยู่ในรายการให้ใช้ 'overview'
// (whitelist ไม่ใช่ blacklist — กันค่าแปลกปลอมหลุดเข้าไปในหน้า)
template.initialTabJson = safeJson(validTab);
```

**2. `Dashboard.html` — รับค่าเข้ามาเป็นตัวแปร JS**

```html
var INITIAL_TAB = <?!= initialTabJson ?>;
```

**3. `Dashboard.js.html` — เปิดแท็บนั้นหลัง login สำเร็จ**

เรียก `switchTab(INITIAL_TAB)` **หลังจากยืนยันสิทธิ์เสร็จแล้วเท่านั้น** — ไม่ใช่ตอน DOM ready เฉยๆ ไม่งั้นจะพยายามโหลดข้อมูลตอนยังไม่มี session แล้ว error

### 🚨 กรณีที่ต้องระวัง (ถ้าไม่ทำ deep-link จะพังเงียบ)

**session หมดอายุแล้วกดปุ่มจาก Rich Menu**

1. เจ้าของกด "💰 รายได้" → เปิด `?page=dashboard&tab=income`
2. session 6 ชม. หมดแล้ว → ระบบพาไป LINE Login
3. login เสร็จ LINE ส่งกลับมาที่ `?code=...&state=...` — **`tab=income` หายไปกับสายลม**
4. ผู้ใช้ตกที่แท็บ overview ทั้งที่กดปุ่ม "รายได้"

**วิธีแก้:** ใช้กลไก `returnTo` ที่มีอยู่แล้ว (ตอนนี้รองรับ `tree:T-001` สำหรับหน้าต้นไม้) — เพิ่มรูปแบบ `dashboard:income`

```
generateOAuthState('dashboard:income')
  -> login เสร็จ -> consumeOAuthState() คืน returnTo
  -> doGet เห็น 'dashboard:' -> เปิด Dashboard พร้อม tab=income
```

`returnTo` ถูกเซ็นรวมใน HMAC อยู่แล้ว จึงปลอมไม่ได้ — ไม่มีช่องโหว่เพิ่ม

**กรณีอื่นที่ต้องเทสต์:**

| สถานการณ์ | ผลที่ต้องได้ |
|---|---|
| `?tab=income` ปกติ | เปิดแท็บรายได้ |
| `?tab=' + alert(1) + '` | ตกไป `overview` ไม่มีอะไรหลุดเข้าหน้า |
| `?tab=` ว่าง / ไม่ส่งมา | `overview` (พฤติกรรมเดิม) |
| `?tab=income` + session หมด | login แล้วกลับมาที่ **income** ไม่ใช่ overview |
| `?tab=users` แต่ผู้ใช้เป็นคนสวน | ถูกปฏิเสธที่ชั้น session เหมือนเดิม (คนสวนเข้า Dashboard ไม่ได้อยู่แล้ว) |
| `liff.state=?page=dashboard&tab=map` | ต้อง parse `tab` ออกมาได้ด้วย |

## 14. ขั้นตอนติดตั้งหลังได้รูปแล้ว

```
1. วางไฟล์ .gs ชุดใหม่ทั้งหมด แล้ว Ctrl+S

6. รัน setupStep2_uploadImages()     -> อัปโหลดรูปให้ครบ 3 เมนู
7. แก้ RICH_MENU_IDS ใน SheetOperations.gs ให้เป็น ID ใหม่
   (admin ใช้ ID เดียวกับ owner)

9. รัน resyncAllRichMenus()          -> ผูกเมนูใหม่ให้ทุกคนตาม role
```

## 15. เทสต์ที่ครอบไว้แล้ว (29 เคส ในชุด `qa4.js`)

- deep-link ทุกแท็บ + ค่าแปลกปลอม (`' + alert(1) + '`, `../../etc`, `<script>`) ต้องตกไป `overview`
- `VALID_DASHBOARD_TABS` **ต้องตรงกับ `id="tab-xxx"` ที่มีจริงใน HTML** (ถ้าเพิ่มแท็บแล้วลืมใส่ whitelist เทสต์จะแดง)
- login แล้วกลับมาแท็บเดิม + **`exchangeLineOAuthCode` ถูกเรียกครั้งเดียว** (เรียกซ้ำ = login พังของจริง เพราะ code ใช้ได้ครั้งเดียว)
- `returnTo` แบบ `tree:` ยังทำงานเหมือนเดิม (ไม่ regress)
- ผัง Rich Menu: ไม่มีปุ่มซ้ำ · พิกัดไม่ทับกัน · ไม่เกินขอบรูป
- **พิสูจน์ว่าเทสต์ไม่หลอกตัวเอง** — จงใจทำให้ปุ่มซ้ำแล้วเช็คว่า `verifyMenuLayouts()` จับได้
- ทุก `action=` ในผังเมนูต้องมี handler จริงใน `Code.gs`
